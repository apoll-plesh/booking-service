## Выводы

Все обязательные проверки по методичке выполнены с ожидаемым результатом.

**Ключевые технические гарантии, подтверждённые вручную:**
1. Защита от пересечений на уровне БД (`EXCLUDE`-ограничение `bookings_no_overlap`) — при конкурентных запросах создаётся ровно одна запись, второй запрос получает 409.
2. Идемпотентность создания — повтор с тем же `Idempotency-Key` не создаёт дубликат; тот же ключ с другими данными → 409.
3. Разграничение доступа на сервере — чужая запись → 404, админ-функция без прав → 403, отсутствие/истечение JWT → 401.
4. Отмена с сохранением истории — `status`, `cancelled_at`, `cancelled_by`, `cancel_reason` записываются, время освобождается.
5. Аудит — события `booking.created` и `booking.cancelled` фиксируются в `audit_events`.

**Ручная проверка не является доказательством отсутствия гонки** — на защите дополнительно демонстрируется `EXCLUDE`-ограничение в БД и транзакция с блокировкой строки ресурса (`FOR SHARE`) в коде.
